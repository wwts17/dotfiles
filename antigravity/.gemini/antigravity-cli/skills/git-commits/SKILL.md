# Git Commits

## Rules

Format: `<type>(<scope>): <subject>`, blank line, optional body and footers.

| type | use | type | use |
|---|---|---|---|
| feat | new feature | refactor | no behavior change |
| fix | bug fix | test | tests |
| docs | documentation | chore | build/tooling |
| style | formatting only | perf | performance |

- Subject: imperative, lowercase, no trailing period, ≤50 chars.
- Body: explains why, not what; wrap at 72.
- Breaking changes: `BREAKING CHANGE: <description>` footer; issue references: `Refs: <ID>`.
- No AI attribution of any kind (`Co-Authored-By`, `Generated by`, ...); the author is the configured git identity.

## Example

❌ `git commit -m "update"` — says nothing about what changed or why.
✅
```
fix(cart): correct tax calculation for EU orders

EU orders must be taxed at the destination country's rate; the
seller's country rate was applied instead.
```
