# 交付产出质量评审

## 核心
依据产出类型套用特定的 Rubric 标准。坚持“先列证据，后定等级”，使用离散三级评级（良好 / 待改进 / 不合格），不给连续数字分。

## 离散评级定义
- **良好**：符合要求，无阻断项，可直接交付。
- **待改进**：可正常使用，但存在可优化的非阻断项。
- **不合格**：存在阻断项（无法运行、误导性逻辑、严重安全隐患）。

## 评审 Rubric

### 1. Skill 规范 / Prompt
- `description` 是否准确触发。
- 是否仅写 Claude 不知道的规则，无无意义的陈词滥调。
- 格式符合 `skill-writer` 模板，思维工具行数 ≤ 35 行。

### 2. 技术文档 (README / API)
- 结构符合 Diátaxis（教程/指南/参考/解释）。
- 前置条件、路径与命令真实可跑。
- 简洁无废话。

### 3. 工程实施计划
- 上下文与目标明确。
- 明确变更文件与代码期望，避免空泛大纲。
- 包含自动化与手动验证方案。

### 4. 代码与 Commit 提交
- 代码符合项目规范（显式错误处理、零值可用）。
- Commit 符合 Conventional Commits，说明变更原因。

## 输出格式
- **类型**：[Skill / 文档 / 计划 / 代码]
- **维度核对**：
  - [维度 A]：良好 | 待改进 | 不合格 — [指到行/段的证据描述]
- **综合判定**：良好 | 待改进 | 不合格（不合格需点出阻断项）
